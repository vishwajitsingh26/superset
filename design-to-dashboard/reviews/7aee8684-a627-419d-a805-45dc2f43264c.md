## Tool surfacing verdict

**Yes, it needs changes.** No model called a tool it wasn't given, and all 16 tool calls succeeded. The problems are in what the prompts *say* about tools:
1. **Envelope example:** `tool_loop.py:58` hard-codes `list_datasets` in every stage's envelope. Use the stage's own tool.
2. **Image paragraph:** inject *"Any image is already attached"* only when `image_paths` is non-empty.
3. **Tool lists:** generate each stage header's "Tools:" line from the same catalogue as the "Tools available to you" section (C lists 2 and defines 3).
4. **Missing inputs:** supply what a stage must report instead of making it discover it through a destructive call (`shared_dataset_id`).
5. **Enforce mandatory calls in code:** e.g. reject a `configure` on a stock type with no capability card unless `get_chart_capabilities` ran. C skipped it and nothing checked.
6. **Registry text:** feed the registry neutral, per-plugin capability text and thumbnails, not stage C rationale from past runs.
7. **Envelope strictness:** stop silently accepting prose-wrapped or bare `final` replies without logging them as protocol violations in `calls.jsonl`.
8. **Stage D control schema:** resolve the shared sections a control panel imports (`legendSection`, `richTooltipSection`, …) into concrete control names, and give D the region crop.
